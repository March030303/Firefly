# git的使用

## 基本概念

## git diff 

1. git diff  或者 git diff --name-only（这样只显示改的文件名）
对比：工作区（你现在正在改的文件） VS 暂存区
看还没 add、没放进暂存的改动。

2. git diff --staged（等价 git diff --cached）
对比：暂存区 VS 最新一次 commit（HEAD）
看已经git add，但还没commit的内容。

3. git diff HEAD
对比：工作区 VS 最近一次提交
不管有没有 add，全部改动一次性看。

4. git diff 分支 A 分支 B
对比：分支 A 的最后一个 commit 和 分支 B 最后一个 commit
比如 git diff main fix/library-and-other-ui，看两个分支提交记录之间的差别。

## git log

1. git log --oneline -4   //查看最近4次commit

## 场景
          
1、（本地在功能分支时）远程main更新了，本地要想拉下来，记得要把本地的commit一下，以免checkout main之后把本地的也带过去，这样远程和本地会冲突pull不过来的

2、后端有新分支在远程了，怎么把他拿过来到本地？
```
git fetch origin

git switch <>（注意这里不用加origin/ —— 只要远端有同名分支且你本地没有，git 会自动创建本地分支并建立跟踪关系（等价于 `git checkout -b <名> origin/<名>`）

git status -sb（检查）

git pull （后续）
```

3、之前远程main分支是A--B--C的时候把代码pull好到本地，则本地main也是A--B--C
此时，本地切feature分支，准备commit D，变成A--B--C--（D），但此时远程main也有commit，变成A--B--C--E了，如何把本地待提交的D提交并拉取main最新代码
```
# 1. 先把当前所有改动提交成一个临时提交（也就是D）
git add -A
git commit -m "wip: study-group 第一版"

# 2. rebase 到最新 main
git fetch origin
git rebase origin/main

# 3. 冲突只会出现在两类文件，处理原则统一：全部取 main 的版本
处理冲突文件
git add -A
git rebase --continue
```

# 测通端口
## 查PID
测所有
```
netstat -ano | findstr :443
```

测本机监听：
```
netstat -ano | findstr "LISTENING" | findstr :443
```
之后会有类似
```                                                                   
 TCP    127.0.0.1:443          0.0.0.0:0              LISTENING       9980
```
 PID是9980，去 任务管理器--详情信息 搜索
